# 실사용 조건 점검 (2026-09-29)

## 방법
- **실데이터(LIVE) 코드 그대로**: 실제 공급자 코드(SEC·Polygon·Finnhub·FRED·FINRA)가 돌아가고, 네트워크만 실제 응답 형식의 고정 응답(`tests/live_fixtures.py`)으로 바꿨습니다.
- **Finnhub 무료 `/quote`의 시간대별 동작 재현**: 정규장 밖에서는 직전 종가를 그 종가 시각으로 돌려줍니다.
- **시각 이동**: 백엔드 프로세스 전체의 시각(벽시계와 캐시 만료용 단조 시계 모두)과 브라우저 시각을 시나리오 시각으로 옮겼습니다.
- **실제 화면으로 조작**: 빈 DB에서 마이그레이션부터 시작했습니다. 데이터 준비·스캔·보유·관심·거래 입력은 화면이 쓰는 HTTP API로 했고, "데이터 준비 시작"과 "다시 스캔하기"는 실제 버튼을 눌렀습니다.
- **점검 범위**: 13개 화면을 1440 px과 820 px로 캡처하고, 콘솔 오류와 HTTP 오류를 수집했습니다.

### 시나리오
| 시나리오 | 조건 |
|---|---|
| 프리마켓 | 06:50 ET에 준비·스캔, 12:02 ET(정규장)에 확인, 화면에서 "다시 스캔" |
| 정규장 | 10:20 ET에 준비·스캔, 10:40 ET에 확인 |
| 새로 설치 | 빈 DB. 준비 전 화면 → 버튼으로 데이터 준비 → 준비 후 화면 |
| 주말 | 금 17:30 ET(애프터마켓)에 스캔, 토 11:00 ET에 확인하고 "종가 기준 다시 스캔" |
| 공급자 장애 | 정규장 스캔 뒤 네트워크 전체 끊김 |

- 시세 스트림(WebSocket)은 이 환경에서 닿지 않아 모든 시나리오에서 "연결 끊김"입니다. 화면은 REST 시세로 동작합니다.

## 확인하지 못한 것
- **실제 공급자 응답으로 돌려보지 않았습니다.** 실제 네트워크와 실제 키로 같은 시나리오를 재현하지 않았습니다. 응답은 실제 형식을 따른 고정 응답입니다.
- **시세 스트림이 연결된 상태**는 이 환경에서 재현하지 못했습니다(스트림 주소에 닿지 않음).
- **점검 도구는 저장소에 넣지 않았습니다.** 시각 이동에 `time-machine`이 필요해 이번 작업 공간에서만 썼습니다.
- **Windows 설치본 화면**은 확인하지 못했습니다.
