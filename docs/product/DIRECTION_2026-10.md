# 방향 전환: 더 적게, 실제 환경에서 확실하게, 가볍게 (2026-10-07)

소유자 결정 (2026-10-07):

| 질문 | 결정 |
|---|---|
| 홈의 중심 | 보유 종목 관리. 대형주 모멘텀은 **참고용**, 전진 모의운영 기록을 몇 달 본 뒤 결정 |
| 종합점수 후보 | 100개 → **상위 20개** |
| 효과가 입증되지 않은 기능 | **기본 꺼짐, 설정에서 켜기** (코드는 남김) |

## 원칙

1. 매일 쓰는 것만 홈에 둡니다. 새 기능은 이 전환이 끝날 때까지 추가하지 않습니다.
2. 가짜 데이터 테스트 통과를 "완료"로 보지 않습니다. 소유자 PC의 **진단 화면**(설정 → 진단) 값으로 확인합니다.
3. 목표: 켠 뒤 홈 3초 안, 화면 응답 95%가 0.3초 안, 15초 넘는 응답 0회, 가만히 둘 때 CPU 2% 이하, 메모리 500MB 이하.

## 단계

1. **측정** (이번): 진단 화면, 후보 100 → 20. 소유자 PC에서 지금 값을 기록합니다.
2. **줄이기:** 홈을 계좌 요약 → 오늘 확인할 일(최대 5개) → 보유 종목 손익으로 정리. 효과 미입증 기능 기본 꺼짐
   (전략 A·C 신호, 매수 구간 알림, 폰 연결 등 — 진단 화면의 "실제로 여는 화면" 기록을 보고 확정).
3. **가볍게:** 꺼진 기능의 백그라운드 계산 중지, 다시 측정.
4. **실환경 확인:** 소유자가 체크리스트로 확인한 뒤 다음으로.

## 1단계에서 바뀐 것

- `config/scoring_model.toml`: `stage4_keep` 100 → 40(전체 분석: 실시간 가격·뉴스·동종 비교), `final_candidates` 100 → 20.
  - 이전에는 100개를 전체 분석한 뒤 상위를 골랐고, 이제 앞 단계 순위 상위 40개만 전체 분석해 20개를 고릅니다.
  - 그래서 최종 20개가 이전 방식의 상위 20개와 다를 수 있습니다(설정 버전 해시가 바뀌어 기록됩니다).
- 실시간 재판정(매초)도 100개 → 20개.
- 스캔 범위 보고에 `ranked_out`(필터는 통과했지만 순위에서 밀려 전체 분석을 하지 않은 종목 수)을 추가했습니다.
- 진단: `GET /api/diagnostics`, 설정 → 진단. 메모리에만 있고 경로 이름만 기록합니다(종목·금액·계좌 정보 없음).
