공개 뉴스 클라이언트 스크립트에서 axios baseURL `/api`, 목록 `/news/list`, 매개변수 `page`, `page_size`, `sort=created_at_desc`와 `news_list` 응답 스키마를 확인했다. 따라서 대상 URL은 `/api/news/list`다. 응답 행의 `id`, `title`, `source`, `created_at`, `tag_names`, `view_count` 필드는 공개 클라이언트 스키마에 존재한다. 상세용 스키마나 인증 token은 사용하지 않는다.

일반 HTTP GET은 홈페이지와 `/api/news/list` 모두 403이었다. 이 환경에서 JSON 수집 성공을 확인하지 못했으므로 실제 연동 성공으로 보고하지 않는다. 옵션은 기본 비활성으로 유지하고, 활성화 시에도 403을 unavailable로 표시한다. 실제 응답 수집 성공까지는 공개 계약을 바탕으로 준비된 Adapter이며 데이터가 채워진 기능이 아니다.

기존 구조: Python/FastAPI + React/TypeScript/Vite, Finnhub/Polygon 가격·Finnhub 뉴스·SEC 재무·FRED 거시, SQLite/SQLAlchemy 저장, 공통 HttpClient/TokenBucket/ProviderChain/HealthRegistry/TTLCache/Refresher. 뉴스는 `NewsItem`, 일정은 `CatalystEvent`, 종목은 ticker와 Security identity로 관리한다. 뉴스 캐시 TTL은 300초, 기본 자동 스캔은 30분, 실시간 재계산은 1초다. 종목 상세의 뉴스·이슈·일정 및 시장 이슈 영역에 보조 뉴스만 연결한다. 기존 점수 모델·계좌·시세·디자인은 바꾸지 않는다.

## 정상 이메일 인증 경로 구현 및 실제 실패 확인

공개 클라이언트의 `emailLoginRequestSchema`와 `userInfoEnvelopeSchema`, axios `post('/auth/login', body)`를 확인했다. 요청은 `/api/auth/login`에 `{email, password}`, 성공 응답은 `user_info` 객체다. 이를 공통 HttpClient로 연결하고 이 클라이언트에 새로 발급되는 자체 세션만 메모리에서 유지하도록 구현했다. 사용자 입력은 MarketLens 로컬 설정에서 받고, 백엔드 작업을 즉시 반환한다. 인증과 뉴스 형식 검증을 모두 통과한 뒤에만 Provider를 설치하고, 기존 캐시를 해당 범위에서 무효화한다. 인증 실패는 자동 반복하지 않는다. 세션 만료 401에는 정상 로그인 한 번으로 복구를 시도한다. 저장 선택은 성공 후에만 OS keyring / 설치 전용 .env로 수행한다.

SaveTicker의 공개 시간 변환 함수 `serverTimeToUserDayjs`는 `dayjs.tz(value, 'Asia/Seoul').tz(userTimezone)`을 사용한다. 따라서 이 Provider에서만 시간대 없는 `created_at`에 명시적으로 KST 정책을 적용한다. 명시된 offset은 그대로 우선하며 원본 문자열은 보존한다. 다른 Provider나 공용 날짜 규칙을 바꾸지 않는다.

2026-10-01 사용자가 로컬 연결 화면에서 정상 계정을 직접 입력했으나 실제 서버 연결은 HTTP 403으로 실패했고 수집은 0건이다. 비밀번호는 로그·보고서·API 응답에 기록하지 않았고, 실패한 계정은 저장하지 않았다. 추가로 일반 HTTP 홈페이지 응답에 `Just a moment...` 제목과 `https://challenges.cloudflare.com` 보안 검증 리소스가 존재하는 것을 확인했다. 이는 해당 서버 접근 경로가 브라우저 보안 검증을 받는 증거다. 계정 비밀번호가 틀렸다는 증거로 삼지 않는다. 정상 계정 인증 구현을 완료해도 현재 환경에서 직접 HTTP 자동 수집은 동작하지 않는다. 허용된 API 접근 경로나 별도로 구현·검증한 정상 브라우저 연동 없이는 자동 수집 완료로 보고할 수 없다.
