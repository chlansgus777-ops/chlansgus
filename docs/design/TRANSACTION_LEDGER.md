# 거래 기록으로 보유 종목 관리 (라운드 10 기능 a)

## 왜

지금은 보유 종목을 "수량·평단" 한 줄로 입력한다. 이 한 줄은 입력한 날의 주식 기준이라, 그 뒤에 주식분할이 있으면 수량과 평단이 틀려진다(9차 H4). 부분 매도의 실현 손익과 배당도 기록할 곳이 없다. 거래를 기록하고 보유는 거래에서 계산하면 분할·매도·배당이 한 규칙으로 처리된다.

## 입력

| 항목 | 내용 | 검사 |
|---|---|---|
| 날짜 | 체결일(뉴욕 날짜) | 미래 날짜 거부 |
| 티커 | 거래 당시의 티커 | 영문 1~10자. 종목은 그날의 `security_id`(이름 변경·재상장 계보)로 정해진다. 같은 CIK의 다른 주식 종류(BRK-A/BRK-B)는 다른 종목 |
| 종류 | BUY / SELL / DIVIDEND / SPLIT | SPLIT은 저장소에 없는 분할을 사용자가 직접 적을 때만 |
| 수량 | 주 | BUY·SELL은 0보다 커야 함. SELL은 그날 보유량 이하 |
| 가격 | 1주 가격(USD) | BUY·SELL은 0보다 커야 함 |
| 수수료 | USD | 0 이상 |
| 금액 | DIVIDEND의 받은 총액(USD) | 0보다 커야 함 |
| 비율 | SPLIT의 분할 전·후 주식 수(예: 1→10) | 둘 다 0보다 커야 함 |

현금은 지금처럼 사용자가 입력하는 계좌 현금을 그대로 쓴다(이 기능은 현금을 계산하지 않는다).

## 계산 규칙 (함수 하나: `domain.ledger.positions`)

1. 거래와 분할을 날짜순으로 처리한다. 같은 날에는 분할을 먼저 적용한다. 분할은 실행일 개장 전에 효력이 생기므로, 그날의 체결은 분할 후 기준이다.
2. 분할: 그 시점 보유 수량 × 비율, 평단 ÷ 비율. 비용 합계와 실현 손익은 변하지 않는다. 분할은 저장소의 분할 기록(종목 계보의 모든 키)과 사용자가 적은 SPLIT을 합친다. 저장소끼리는 같은 날·같은 비율이면 한 번, 사용자 SPLIT은 같은 비율의 저장된 분할이 30일 안에 있으면 그 분할로 본다(권리락일과 입고일 차이). 비율은 1/10,000~10,000배만 받는다. 보유가 0일 때의 분할은 목록에 넣지 않는다.
3. BUY: 수량 += q, 비용 += q × 가격 + 수수료, 평단 = 비용 ÷ 수량.
4. SELL: q ≤ 보유 수량. 실현 손익 += q × (가격 − 평단) − 수수료, 비용 −= q × 평단.
5. DIVIDEND: 배당 합계 += 금액(실현 손익과 따로 보여 준다).
6. 평가: 미실현 손익 = 수량 × (종가 − 평단). 종가는 분할 반영된 저장 일봉이다.
7. 종목 단위: 거래는 그날의 `security_id`에 속한다(읽을 때 계산하므로 나중에 알게 된 재사용도 반영). 티커 재사용 뒤 새 종목은 옛 종목의 거래를 물려받지 않는다. 이름 변경·재상장 뒤에는 같은 종목으로 이어지고, 보유는 지금 쓰는 티커로 표시한다(옛 이름으로만 적힌 거래도).
8. 한 종목의 거래 기록에 매수가 있으면 그 종목의 보유는 거래에서 계산한다. 수동 입력 줄은 쓰지 않고 그 사실을 알림으로 보여 준다(전량 매도한 경우 포함). 배당·분할만 적힌 종목은 수동 입력 줄을 그대로 쓴다. 거래 기록이 없는 종목은 지금처럼 수동 입력을 쓴다(9차 H4의 분할 환산 포함, 입력한 날의 종목 기준).

## 실패 모드와 처리

| 실패 | 처리 |
|---|---|
| 보유보다 많이 매도 | 저장하지 않음. "그날 보유 n주보다 많이 매도할 수 없음" |
| 과거 거래를 지워 뒤의 매도가 보유보다 많아짐 | 삭제하지 않음. 이유를 알려 줌 |
| 나중에 들어온 분할 기록 때문에 이미 깨진 기록 | 보유 칸에 오류를 보여 줌. 그 오류와 무관한 추가·삭제는 받고, 새로 깨거나 더 앞당기는 변경만 거부 |
| 보유가 없는데 매도(아주 작은 수량 포함) | 저장하지 않음 |
| 미래 날짜, 0 이하 수량·가격, 음수 수수료 | 저장하지 않음 |
| 같은 분할이 저장소와 사용자 SPLIT 양쪽에 있음 | 한 번만 적용 |
| 종가가 없음 | 수량·평단·실현 손익은 보이고, 평가·미실현은 "가격 없음" |
| 거래 뒤 티커가 다른 회사로 재사용됨 | 옛 거래는 옛 종목(보관 키)에 남음. 새 종목 보유는 0부터. 재사용 전에 입력한 수동 줄도 새 회사 가격으로 평가하지 않음 |

## 불변 조건 (테스트로 매번 확인)

- 분할 불변: 같은 거래를 분할 전 기준(수량 q, 가격 p)으로 적든 분할 후 기준(q×r, p÷r)으로 적든, 평가금액·비용·실현·미실현 손익이 같다.
- 순서 무관: 같은 날짜 순서가 정해진 거래 목록이면 입력한 순서와 무관하게 결과가 같다.
- 보존: 매도 수량 합 ≤ 매수 수량 합(분할 반영), 보유 수량 ≥ 0.
- 시점: `as_of` 날짜의 보유는 그 날짜까지의 거래와 분할만 쓴다.
- 종목: 티커 재사용 뒤 새 종목의 보유는 옛 종목 거래를 포함하지 않고, 같은 회사의 다른 주식 종류는 서로 섞이지 않는다.
- 책임: 변경은 그 변경이 새로 만든 매도 초과에 대해서만 거부된다.
- 한도 계산과 매수 금액 계산은 이 보유를 그대로 쓴다(한도 불변 조건 테스트에 포함).

## 코드 리뷰 뒤 바뀐 점 (라운드 10)

`/code-review max`가 찾은 결함 13건을 반영했다. 가장 큰 것은 '같은 회사'를 CIK로 판단해 같은 CIK의 두 주식 종류(BRK-A/BRK-B)가 한 보유로 합쳐지던 것이다. 같은 규칙을 쓰던 추천 이력·직전 판단(F10 수정)에도 같은 결함이 있어 함께 고쳤다(`MarketStore.security_id`). 이제는 종목 계보가 같은 종목을 정한다.
